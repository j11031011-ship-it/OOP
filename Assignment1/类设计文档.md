## 题目 1：图书馆借书、还书场景

### 1.1 业务流程分析

借书流程：

```
学生发起借书请求 → 管理员核验学生资格（是否达借阅上限、有无欠款）
→ 管理员核验书籍状态（是否在馆）→ 更新书籍状态为"已借出"
→ 将书加入学生借阅列表 → 设定应还日期
```

还书流程：

```
学生提交还书 → 管理员将书籍状态改回"在馆"
→ 从学生借阅列表中移除 → 检查是否逾期，逾期则计算欠款
```

由流程得出职责划分：**Book** 只负责描述自身与状态；**Student** 维护自己的借阅记录；**Librarian** 负责审核与状态变更（封装：学生不能直接修改书籍状态）。

### 1.2 类定义

| 成员 | 定义 | 说明 |
|---|---|---|

| - name: string | 姓名 | |

方法：

| 定义 | 说明 |
|---|---|
| + borrowBook(book: Book): bool | 发起借书请求（实际入账由管理员完成） |
| + returnBook(book: Book): bool | 发起还书请求 |
| + queryBorrowed(): List&lt;Book&gt; | 查询在借书目 |
| + payFine(amount: double): void | 缴纳欠款 |
| + canBorrow(): bool | 是否满足借书条件（未超上限且无欠款） |

#### Book（书籍）

| 成员 | 定义 | 说明 |
|---|---|---|
| - isbn: string | 书号 | 唯一标识 |
| - title: string | 书名 | |

#### Librarian（大学图书馆的管理员）

| 成员 | 定义 | 说明 |
|---|---|---|
| - staffId: string | 工号 | 唯一标识 |
| - name: string | 姓名 | |
| - department: string | 所属馆区/部门 | |

方法：

| 定义 | 说明 |
|---|---|
| + handleBorrow(student: Student, book: Book): bool | 处理借书：核验 student.canBorrow() 与 book 状态，调用 markBorrowed() 并更新学生列表 |
| + handleReturn(student: Student, book: Book): double | 处理还书：调用 markReturned()，逾期则计算并登记欠款 |
| + addNewBook(book: Book): void | 新书入库登记 |
| + removeBook(book: Book): void | 图书注销 |
| + remindOverdue(): void | 向逾期学生发送催还通知 |

### 1.3 类间关系（UML 关联）

```
Student "1" ──── 借阅(0..*) ──── "1" Book
    │                                │
    │ 发起请求                        │ 状态被修改
    ▼                                ▼
Librarian "1" ──── 管理(处理借还、入库) ────▶ Student / Book
```

- **Student ↔ Book**：关联关系（association），多重性 `1 对 0..*`（一名学生可同时借 0~N 本书）。
- **Librarian → Book / Student**：依赖/关联关系（管理员操作两者，但并不"拥有"它们）。

## 题目 2：三个视角下的"汽车"类

### 2.1 设计思想

同一辆"汽车"，不同角色关心的事情完全不同——**视角决定抽象边界**：

- 厂家关心"生产与质量追溯"，车是**产品**；
- 车主关心"使用与保养"，车是**交通工具/财产**；
- 交管机构关心"合规与监管"，车是**登记对象**。

因此三个类的属性几乎不重叠，这正是本题要表达的面向对象抽象思想。

#### CarFromManufacturer（厂家视角的汽车——产品）

| - model: string | 车型 | |
| - trim: string | 配置版本 | |
| - color: string | 车身颜色 | |
| - productionDate: Date | 出厂日期 | |
| - batchNo: string | 生产批次号 | 召回追溯用 |
| - qualityResult: bool | 出厂检验结果 | |

方法：

| 定义 | 说明 |
|---|---|
| + inspect(): bool | 出厂质量检测 |
| + recall(batchNo: string): void | 按批次发起召回 |
| + traceBatch(vin: string): string | 按 VIN 追溯生产批次与零部件来源 |

#### CarFromOwner（车主视角的汽车——交通工具）

| 成员 | 定义 | 说明 |
|---|---|---|
| - plateNo: string | 车牌号 | |
| - mileage: double | 里程数（km） | |

| 定义 | 说明 |

| + maintain(): void | 保养并写入保养记录 |

#### CarFromAuthority（交通管理机构视角的汽车——监管对象）

| 成员 | 定义 | 说明 |
|---|---|---|
| - plateNo: string | 车牌号 | 登记标识 |
| - vin: string | 车架号 | 与车辆实体一一对应 |
| - ownerName: string | 登记车主 | |
| - vehicleType: string | 车辆类型 | 小型轿车/货车等 |

| - violations: List&lt;Violation&gt; | 违章记录 | |

方法：

| 定义 | 说明 |
|---|---|
| + register(owner: string): void | 注册登记上牌 |
| + annualInspection(): bool | 年检审核并更新状态 |
| + recordViolation(v: Violation): void | 登记违章 |
| + revokePlate(): void | 注销牌照 |

### 2.3 类间关系

三个类相互独立（无关联），因为三个角色互不知晓对方的数据；若想体现"同一实体"，可在报告文字中说明三者通过 `VIN / 车牌号` 在现实层面指向同一辆车，但建模上不建立依赖。
